CONFIGURATION

config.json 設定マニュアル

シフト自動作成システムの動作ルールを定義する設定ファイルです。変更時は「名前の完全一致」と「JSONの文法（カンマの有無、ダブルクォーテーション等）」に注意してください。

PROJECT

1. プロジェクト設定 (project_name)

概要: アプリケーションの名称設定です。
役割: ログ出力時などの識別に利用されます。（システム動作への直接的な影響はありません）

設定例

"project_name": "ShiftScheduler_v2_Rich"

例の意味: アプリケーションの名称を「ShiftScheduler_v2_Rich」として定義しています。

TIME SLOTS

2. 時間枠設定 (time_slots)

概要: 1日のスケジュールを分割する枠（コマ）の定義です。

設定項目詳細

  • "id": システム内部および requirements（必要人数設定）で参照するための識別キーです（例: "t_1000"）。
  • "label": 重要: members.csv の時間ヘッダー名、および出力Excelの行名と完全に一致させる必要があります。
  • "is_business_hour":
    • true: シフト（役職）の割り当て計算が行われる対象時間です。
    • false: 準備や片付けなど、シフト割り当ての対象外とする時間です。人員不足の判定などから除外されます。

設定例

"time_slots": [
  { "id": "t_0800", "label": "08:00(準備)", "is_business_hour": false },
  { "id": "t_1000", "label": "10:00",       "is_business_hour": true },
  { "id": "t_1100", "label": "11:00",       "is_business_hour": true }
]

例の意味: 8:00は準備時間（シフト割当対象外）、10:00と11:00は営業時間（シフト割当対象）として定義しています。

ROLES

3. 役職設定 (roles)

概要: 割り当てる業務の種類と、それに付随するルールの定義です。

基本設定項目

  • キー ("cashier", "promo" 等): システム内部で参照するための役職IDです。
  • "name": 重要: members.csv の「役職」および「責任者」列に入力される名称と完全に一致させる必要があります。
  • "requires_leader" (true/false): true にすると、その時間帯のその役職には、CSVの「責任者」列に該当役職を持つスタッフが最低1名必須となります。
  • "color_code": Excel出力時の背景色（16進数カラーコード）です。

特殊ルール設定 (special_constraints)

  • "description": 管理者向けのメモです。計算には影響しません。
  • "continuity_preference": 連続勤務の扱いを指定します。"maximize" に設定すると、ソフトルール continuity_bonus が有効な場合、できるだけ同じ人が連続して担当するようにスコアが加算されます。
  • "min_break_length": この役職に就いたあとに必要な最低休憩コマ数です。
  • "fill_priority": 人手不足が発生した場合の穴埋め優先度です（"high": 高優先、"normal": 普通、"low": 低優先）。

設定例

"roles": {
  "cashier": {
    "name": "レジ",
    "requires_leader": false,
    "color_code": "#FFD700"
  },
  "promo": {
    "name": "宣伝",
    "requires_leader": false,
    "special_constraints": {
      "description": "できるだけ長く入り、休憩は短くてよい",
      "continuity_preference": "maximize", 
      "min_break_length": 1,
      "fill_priority": "high"
    },
    "color_code": "#87CEEB"
  }
}

例の意味: 「レジ」は責任者不要の通常役職、「宣伝」は連続勤務を推奨し、人員補充の優先度が高い特殊ルールの役職として定義しています。

REQUIREMENTS

4. 必要人数設定 (requirements)

概要: 各時間枠において、どの役職が何人必要かの基準値です。

設定項目詳細

"default_rule" の中に、時間枠の "id"（time_slots で定義したもの）をキーとして、役職IDと必要人数のペアを指定します。

設定例

"requirements": {
  "default_rule": {
    "t_1000": { "cashier": 3, "pc_corner": 4, "promo": 3, "fair": 2 },
    "t_1100": { "cashier": 3, "pc_corner": 4, "promo": 3, "fair": 2 }
  }
}

例の意味: 10:00および11:00の時間帯に、レジ3名、PCコーナー4名、宣伝3名、射的2名が必要であることを定義しています。

CONSTRAINTS

5. 計算制約設定 (constraints)

概要: シフトを自動生成する際のルールの「厳しさ」や「優先度」の定義です。

絶対条件 (hard)

true （または enabled: true）になっているルールは絶対に守られます。満たせない場合はシフト作成が失敗します。

  • "single_role_per_slot": 1人のスタッフが同じ時間帯に複数の役職を兼任することを禁止します。
  • "availability": 営業時間外、またはスタッフが出勤不可（×）の時間の割り当てを禁止します。
  • "requirement_check": requirements で設定した必要人数を必ず満たすよう強制します（false にすると人数不足でも計算が通ります）。
  • "leader_check": requires_leader が true の役職に、責任者を必ず1名以上配置するよう強制します。
  • "max_consecutive_shift": 連続勤務に関する詳細設定です。
    • "max_work_hours": 連続して勤務できる最大コマ数です。
    • "min_break_length": 上記の勤務後に必ず取得させる最小休憩コマ数です。

努力目標 (soft)

enabled: true で有効化されます。weight（重み）の数値が大きい制約ほど、優先的に満たそうと努力します。

  • "minimize_shortage": 人手不足を最小限に抑えるよう努力します（※ requirement_check が false の場合のみ意味を持ちます）。
  • "avoid_emergency": CSVで緊急時のみ（△）と申告したスタッフの起用を避けるように努力します。
  • "prefer_desired_role": スタッフが担当可能と申告した役職を優先的に割り当てるように努力します。
  • "continuity_bonus": continuity_preference が "maximize" になっている役職で、同じ人が連続して担当するように努力します。

設定例

"constraints": {
  "active_rules": {
    "hard": {
      "single_role_per_slot": true,
      "availability": true,
      "requirement_check": true,
      "leader_check": true,
      "max_consecutive_shift": {
        "enabled": true,
        "max_work_hours": 8,
        "min_break_length": 1
      }
    },
    "soft": {
      "minimize_shortage": false,
      "avoid_emergency": { "enabled": true, "weight": 1000 },
      "prefer_desired_role": { "enabled": true, "weight": 10 },
      "continuity_bonus": { "enabled": true, "weight": 30 }
    }
  }
}

例の意味: 絶対条件として人数や責任者の確保、最大連続勤務8コマ・休憩1コマを必須とし、優先条件として緊急出勤の回避を最優先（重み1000）するように定義しています。

KEYWORDS

6. キーワード設定 (keywords)

概要: members.csv の入力テキストと、システム内の出勤可否ステータスの紐付けです。

設定項目詳細

  • "available": 通常出勤として扱うキーワードのリストです。
  • "emergency": 人手不足時（緊急時）のみ出勤として扱うキーワードのリストです。
  • "unavailable": 出勤不可として扱うキーワードのリストです。

注意: ここに定義されていない文字列がCSVに存在した場合、システムはエラーとなり計算を停止します。入力者の表記揺れがある場合はリストに追加してください。

設定例

"keywords": {
  "available": ["可能", "〇", "OK"],
  "emergency": ["いざとなれば", "△", "緊急", "どうしてもなら可"],
  "unavailable": ["x", "×", "不可", "-", "未定", "不可能"]
}

例の意味: 「〇」や「OK」は通常出勤、「△」や「緊急」は緊急枠、「×」や「-」は出勤不可としてシステムに認識させます。

TROUBLESHOOTING

設定起因のエラー

Q. 「シフト作成失敗」「条件が厳しすぎるか、人数が不足しています」と表示される

  • 原因: 出勤可能人数に対し requirements の必要人数が多すぎるか、担当可能役職に偏りがあります。
  • 対処: コンソールの「不足分析レポート」を確認し、requirements の要求人数を下げるか、絶対ルール（hard）を一時的に false にして再計算してください。
